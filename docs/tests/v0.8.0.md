## 共通前提

| 項目 | 値 |
|------|-----|
| 対象（JS） | `@b4moss/crudian/bun-sqlite` / `drizzle` / `prisma` / `libsql` |
| 対象（Go） | `github.com/b4moss/crudian/go/gorm` / `.../go/libsql`（共有 `go/crudian`） |
| 契約の正 | 共有層の語彙。参照実装の詳細確認は bun-sqlite。他アダプタ・Go は同等観測 |
| 入口 | 既存どおり（JS: `createCrud(db)`、Go: `CreateCrud(db)`） |
| `SearchQuery` 追加 | `paging?: "offset" \| "cursor"`（**未指定 = `"offset"`**）、`offset?: number`（offset 時。未指定 = `0`） |
| offset 戻り値 | `{ items, total, offset, limit, hasMore }`（`nextCursor` を含めない） |
| cursor 戻り値 | `{ items, nextCursor, hasMore, total }`（`offset` / `limit` フィールドを含めない） |
| `total` | where 全件数（limit / offset / cursor 非依存）。`count(table, { where })` と同値 |
| `hasMore`（offset） | `offset + items.length < total` |
| `hasMore`（cursor） | 既存どおり（`limit + 1` 取得による続き判定） |
| 並び | 両モードとも当面 `id` 昇順固定 |
| 相反入力 | offset モードで `cursor` を渡す / cursor モードで `offset` を渡す → **拒否**（独自最小エラー） |
| `list` | 引き続き `search` の別名（同じ入力・同じ戻り） |
| `count` | 対象外（契約変更なし） |
| 識別子 / エラー | 既存どおり（文字列必須・形式検証なし。独自エラー最小。他は下位例外） |
| 対象外（本ファイル） | 全文検索、orderBy、可変 PK、`count` 契約変更、PHP |

フィクスチャ表（例）は整数主キー `id` を持つ単表。スキーマはテスト内 DDL で用意してよい。  
v0.1〜v0.7 の CRUD / 条件ビルダー / extended writes / `count` は回帰として壊さない。  
**契約変更（破壊的）:** 未指定の `search` / `list` は **offset モード**になる。cursor 挙動が必要な呼び出しは `paging: "cursor"` を明示する。

### 表記の固定

| 項目 | 決定 |
|------|------|
| 切り替え | 明示 `paging?: "offset" \| "cursor"` |
| デフォルト | `"offset"`（破壊的変更 OK） |
| offset 入力 | `offset`（default `0`）+ `limit`（default `20`） |
| cursor 入力 | 既存の `cursor` + `limit` |
| offset 戻り値 | `{ items, total, offset, limit, hasMore }` |
| cursor 戻り値 | `{ items, nextCursor, hasMore, total }` |
| 相反 | 拒否（独自最小エラー） |
| Go 戻り値 | 1 struct。offset 時は `NextCursor` を nil、`Offset`/`Limit` を載せる。cursor 時は `Offset`/`Limit` を 0、`NextCursor` を載せる |

## bun-sqlite（参照実装）

パッケージ: `@b4moss/crudian/bun-sqlite`  
ランタイム / テスト: Bun + `bun:test`  
DB: 呼び出し側注入の `bun:sqlite` `Database`（テストでは `:memory:`）

### bun.searchOffset

- 未指定または `paging: "offset"` のとき offset ページングする
- SQL イメージ: `SELECT ... FROM table [WHERE ...] ORDER BY id ASC LIMIT ? OFFSET ?`
- 戻りは `{ items, total, offset, limit, hasMore }`（`nextCursor` キーなし）

#### テスト：正常系

- クエリ未指定（または `paging` 未指定）で offset モードになり、`offset === 0`・`limit` はデフォルト（20）・キーに `offset` / `limit` があり `nextCursor` がない
- `paging: "offset"` 明示も未指定と同じ形（破壊的デフォルトと明示指定が一致）
- N=5, `limit=2` で1ページ目: `items.length === 2`、`offset === 0`、`hasMore === true`、`total === 5`
- 2ページ目 `{ offset: 2, limit: 2 }` で続きの id が重複なく取れ、`offset === 2`。最終ページで `hasMore === false`
- `where` ありで一致 M 件のとき、どのページでも `total === M`（`count(table, { where })` と同値）
- `offset >= total`（例: N=5, `offset: 10`）のとき `items` は空、`hasMore === false`、`total === N`、返却の `offset` / `limit` は入力どおり
- 0件のとき `items` は空、`hasMore === false`、`total === 0`、`offset` / `limit` は入力どおり（またはデフォルト）

#### テスト: 異常系

- `paging: "offset"`（または未指定）で `cursor` を渡すと拒否する（`CrudianError`）
- 負の `offset`、非数 / 非有限の `offset` は拒否する
- 不正な `limit`（0 以下・非数等）は既存どおり拒否する
- 不正な `paging`（`"offset"` / `"cursor"` 以外）は拒否する

---

### bun.searchCursor

- `paging: "cursor"` のとき既存の id 昇順 keyset を維持する
- 戻りは `{ items, nextCursor, hasMore, total }`（`offset` / `limit` キーなし）

#### テスト：正常系

- `paging: "cursor", limit: 2` で1ページ目の `nextCursor` / `hasMore` / `total` が v0.5.0 どおり進む
- `cursor` を進めた2ページ目以降でも `total` は全件数のまま
- 最終ページで `hasMore === false`、`nextCursor === null`

#### テスト: 異常系

- `paging: "cursor"` で `offset` を渡すと拒否する（`CrudianError`）
- 不正な `cursor` 型は既存どおり拒否する
- 不正な `limit` は既存どおり拒否する

---

### bun.listPaging

- `list` は `search` の別名であり、offset / cursor いずれでも同一結果を返す

#### テスト：正常系

- 同じ offset クエリで `list` と `search` が deep equal
- 同じ cursor クエリ（`paging: "cursor"`）で `list` と `search` が deep equal

#### テスト: 異常系

- `search` と同じ相反入力で同じ拒否になる

---

### bun.regressionPaging

- 破壊的変更後も、明示 `paging: "cursor"` で旧 cursor 回帰が通る
- CRUD / `count` / extended writes のスモークは壊さない

#### テスト：正常系

- `create` → `read` が行を返す
- `count` が where 件数を返す（本版で契約を変えない）
- `paging: "cursor"` のページングが v0.5.0 相当で動く

#### テスト: 異常系

- （本版で入口・`count` の拒否は変えない）

## Go（同等契約）

パッケージ: `github.com/b4moss/crudian/go/gorm` / `.../go/libsql`  
共有実装: `github.com/b4moss/crudian/go/crudian`  
ランタイム / テスト: Go 1.26+ + `testing`

### gorm.searchPaging / libsql.searchPaging

- `SearchQuery.Paging` が `""` または `"offset"` のとき offset モード（`Offset` 未指定は 0）
- `"cursor"` のとき既存 keyset
- `List` は `Search` の別名

#### テスト：正常系

- `Paging` 未指定で offset モード。結果に `Offset` / `Limit` が載り、`NextCursor` は nil
- `Paging: "offset"` 明示も未指定と同じ形
- offset でページが進む（`HasMore` / `Total` 含む）。`Offset >= Total` なら空・`HasMore == false`
- `Paging: "cursor"` で旧 cursor ページングが維持される
- 同じクエリで `List` と `Search` が同等

#### テスト: 異常系

- offset モードで `Cursor != nil` のとき拒否する
- cursor モードで `Offset` を渡したとき拒否する（ポインタ非 nil 等、明示入力として判別できる形）
- 負の `Offset` / 不正 `Limit` / 不正 `Paging` を拒否する

（gorm / libsql は同等観測。厚いケースはどちらか一方でもよいが、両アダプタでスモークは通す）
