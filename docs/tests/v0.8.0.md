`count()` 契約は変更しない（v0.5.0 / #47 のまま）。

## 共通前提

| 項目 | 値 |
|------|-----|
| 対象（JS） | `@b4moss/crudian/bun-sqlite` / `drizzle` / `prisma` / `libsql` |
| 対象（Go） | `github.com/b4moss/crudian/go/gorm` / `.../go/libsql`（共有 `go/crudian`） |
| 契約の正 | 共有層の語彙。参照実装の詳細確認は bun-sqlite。他アダプタ・Go は同等観測 |
| 入口 | 既存どおり（JS: `createCrud(db)`、Go: `CreateCrud(db)`） |
| `SearchQuery` 追加 | `paging?: "offset" \| "cursor"`（**未指定 = `"offset"`**）、`offset?: number`（offset 時。未指定 = `0`） |
| offset 戻り値 | `{ items, total, offset, limit, hasMore }`（`nextCursor` を含めない） |
| cursor 戻り値 | `{ items, nextCursor, hasMore, total }`（`offset` / `limit` フィールドを含めない） |
| `total` | where 全件数（limit / offset / cursor 非依存）。`count(table, { where })` と同値 |
| `hasMore`（offset） | `offset + items.length < total` |
| `hasMore`（cursor） | 既存どおり（`limit + 1` 取得による続き判定） |
| 並び | 両モードとも当面 PK 列（デフォルト `id`。#72 で変更可）の昇順 |
| 相反入力 | offset モードで `cursor` を渡す / cursor モードで `offset` を渡す → **拒否**（独自最小エラー） |
| `list` | 引き続き `search` の別名（同じ入力・同じ戻り） |
| `count` | 対象外（契約変更なし） |
| 識別子 / エラー | 既存どおり（文字列必須・形式検証なし。独自エラー最小。他は下位例外） |
| 対象外（#90 節） | 全文検索、orderBy、`count` 契約変更、PHP |

フィクスチャ表（例）は整数主キー `id` を持つ単表。スキーマはテスト内 DDL で用意してよい。  
v0.1〜v0.7 の CRUD / 条件ビルダー / extended writes / `count` は回帰として壊さない。  
**契約変更（破壊的）:** 未指定の `search` / `list` は **offset モード**になる。cursor 挙動が必要な呼び出しは `paging: "cursor"` を明示する。

### 表記の固定

| 項目 | 決定 |
|------|------|
| 切り替え | 明示 `paging?: "offset" \| "cursor"` |
| デフォルト | `"offset"`（破壊的変更 OK） |
| offset 入力 | `offset`（default `0`）+ `limit`（default `20`） |
| cursor 入力 | 既存の `cursor` + `limit` |
| offset 戻り値 | `{ items, total, offset, limit, hasMore }` |
| cursor 戻り値 | `{ items, nextCursor, hasMore, total }` |
| 相反 | 拒否（独自最小エラー） |
| Go 戻り値 | 1 struct。offset 時は `NextCursor` を nil、`Offset`/`Limit` を載せる。cursor 時は `Offset`/`Limit` を 0、`NextCursor` を載せる |

## bun-sqlite（参照実装）

パッケージ: `@b4moss/crudian/bun-sqlite`  
ランタイム / テスト: Bun + `bun:test`  
DB: 呼び出し側注入の `bun:sqlite` `Database`（テストでは `:memory:`）

### bun.searchOffset

- 未指定または `paging: "offset"` のとき offset ページングする
- SQL イメージ: `SELECT ... FROM table [WHERE ...] ORDER BY id ASC LIMIT ? OFFSET ?`
- 戻りは `{ items, total, offset, limit, hasMore }`（`nextCursor` キーなし）

#### テスト：正常系

- クエリ未指定（または `paging` 未指定）で offset モードになり、`offset === 0`・`limit` はデフォルト（20）・キーに `offset` / `limit` があり `nextCursor` がない
- `paging: "offset"` 明示も未指定と同じ形（破壊的デフォルトと明示指定が一致）
- N=5, `limit=2` で1ページ目: `items.length === 2`、`offset === 0`、`hasMore === true`、`total === 5`
- 2ページ目 `{ offset: 2, limit: 2 }` で続きの id が重複なく取れ、`offset === 2`。最終ページで `hasMore === false`
- `where` ありで一致 M 件のとき、どのページでも `total === M`（`count(table, { where })` と同値）
- `offset >= total`（例: N=5, `offset: 10`）のとき `items` は空、`hasMore === false`、`total === N`、返却の `offset` / `limit` は入力どおり
- 0件のとき `items` は空、`hasMore === false`、`total === 0`、`offset` / `limit` は入力どおり（またはデフォルト）

#### テスト: 異常系

- `paging: "offset"`（または未指定）で `cursor` を渡すと拒否する（`CrudianError`）
- 負の `offset`、非数 / 非有限の `offset` は拒否する
- 不正な `limit`（0 以下・非数等）は既存どおり拒否する
- 不正な `paging`（`"offset"` / `"cursor"` 以外）は拒否する

---

### bun.searchCursor

- `paging: "cursor"` のとき既存の id 昇順 keyset を維持する
- 戻りは `{ items, nextCursor, hasMore, total }`（`offset` / `limit` キーなし）

#### テスト：正常系

- `paging: "cursor", limit: 2` で1ページ目の `nextCursor` / `hasMore` / `total` が v0.5.0 どおり進む
- `cursor` を進めた2ページ目以降でも `total` は全件数のまま
- 最終ページで `hasMore === false`、`nextCursor === null`

#### テスト: 異常系

- `paging: "cursor"` で `offset` を渡すと拒否する（`CrudianError`）
- 不正な `cursor` 型は既存どおり拒否する
- 不正な `limit` は既存どおり拒否する

---

### bun.listPaging

- `list` は `search` の別名であり、offset / cursor いずれでも同一結果を返す

#### テスト：正常系

- 同じ offset クエリで `list` と `search` が deep equal
- 同じ cursor クエリ（`paging: "cursor"`）で `list` と `search` が deep equal

#### テスト: 異常系

- `search` と同じ相反入力で同じ拒否になる

---

### bun.regressionPaging

- 破壊的変更後も、明示 `paging: "cursor"` で旧 cursor 回帰が通る
- CRUD / `count` / extended writes のスモークは壊さない

#### テスト：正常系

- `create` → `read` が行を返す
- `count` が where 件数を返す（本版で契約を変えない）
- `paging: "cursor"` のページングが v0.5.0 相当で動く

#### テスト: 異常系

- （本版で入口・`count` の拒否は変えない）

## 可変 PK（#72）

本節は **#72（主キー列名を `id` 以外にも指定可能にする）** の受け入れを扱う。  
`search` / `list` の `paging` 契約は変更しない（上記 #90 のまま）。

### 共通前提（#72）

| 項目 | 値 |
|------|-----|
| 対象（JS） | `@b4moss/crudian/bun-sqlite` / `drizzle` / `prisma` / `libsql` |
| 対象（Go） | `github.com/b4moss/crudian/go/gorm` / `.../go/libsql`（共有 `go/crudian`） |
| 契約の正 | 共有層の語彙。参照実装の詳細確認は bun-sqlite。他アダプタ・Go は同等観測 |
| 入口（JS） | `createCrud(db, options?)`。`options?: { pk?: string }` |
| 入口（Go） | `CreateCrud(db, opts ...Options)`。`Options{ PK string }` |
| デフォルト PK | `"id"`（第2引数省略・空オプション・`PK == ""` はすべて `"id"`） |
| カスタム PK | 非空文字列。CRUD インスタンス単位（テーブルごとではない） |
| 列存在チェック | 対象テーブルへの **初回操作時**に検証。列が無ければ独自最小エラーで拒否 |
| 影響メソッド | `create`（sync の再読込）、`search` / `list`（ORDER BY / cursor / `nextCursor`）、`upsert`、`duplicate`、`bulkUpsert` |
| 識別子 / エラー | 既存どおり（文字列必須。独自エラー最小。他は下位例外） |
| 対象外（#72 節） | 複合 PK、PK 型の変更、orderBy 一般化、全文検索、PHP、Dialect の PG/MySQL |

#### 表記の固定（#72）

| 項目 | 決定 |
|------|------|
| オプションキー | JS: `pk` / Go: `PK` |
| デフォルト | `"id"`（後方互換。既存呼び出しは変更不要） |
| 空文字 `pk` / `PK` | 拒否（独自最小エラー）。黙って `"id"` に落とさない |
| 非文字列 `pk`（JS） | 拒否 |
| 列が無いとき | 独自最小エラー（例: `pk column "…" does not exist on table "…"`）。SQLite 例外に任せない |
| upsert / bulkUpsert | conflict / 必須キーは設定された PK 列名 |
| duplicate | 設定された PK 列をコピーせず、採番（または呼び出し側の overrides）に任せる |
| cursor / 並び | 当面 PK 列の昇順。`nextCursor` は生の PK 値 |
| フィクスチャ（デフォルト） | 整数主キー `id` の単表（既存どおり） |
| フィクスチャ（カスタム） | 例: `item_id INTEGER PRIMARY KEY AUTOINCREMENT` の単表。スキーマはテスト内 DDL で用意してよい |

v0.1〜v0.7 および本ファイル #90 節の CRUD / 条件ビルダー / extended writes / `count` / `paging` は回帰として壊さない。  
**契約追加（非破壊）:** 第2引数省略時の振る舞いは従来どおり。`pk` 指定時のみ PK 列名が切り替わる。

### bun-sqlite（参照実装・#72）

パッケージ: `@b4moss/crudian/bun-sqlite`  
ランタイム / テスト: Bun + `bun:test`  
DB: 呼び出し側注入の `bun:sqlite` `Database`（テストでは `:memory:`）

#### bun.createCrudPk

- `createCrud(db)` / `createCrud(db, {})` / `createCrud(db, { pk: "id" })` は従来どおり `id` を PK として使う
- `createCrud(db, { pk: "item_id" })` は `item_id` を PK として使う

##### テスト：正常系

- 第2引数省略で既存の `id` 表に対する create / read / upsert が従来どおり動く
- `{ pk: "id" }` 明示も省略と同じ観測になる
- `{ pk: "item_id" }` で `item_id` 表に create すると返却行に採番された `item_id` が入る
- カスタム PK の CRUD を `id` 表に対して使うと、列不存在エラーになる（次節）

##### テスト: 異常系

- `pk: ""` を拒否する（`CrudianError`）
- `pk` が文字列でないとき拒否する
- `db` 不正は既存どおり拒否する

---

#### bun.pkColumnMissing

- 指定した PK 列が対象テーブルに存在しないとき、操作を拒否する
- 検証はテーブルへの初回操作で行い、以降はキャッシュしてよい（観測は「拒否されること」）

##### テスト：正常系

- （本節は異常系が主。列が存在するカスタム PK 表では create が成功する）

##### テスト: 異常系

- `{ pk: "item_id" }` の CRUD で、`id` のみ持つ表へ create / read / search / upsert 等を行うと拒否する
- エラーは独自最小エラー（`CrudianError`）。メッセージに PK 列名とテーブル名が分かる
- 存在しないテーブル参照は従来どおり SQLite 例外（本チェックより先に失敗してよい）

---

#### bun.pkCreateRead

- sync `create` は挿入後、設定 PK で対象行を再読込して返す

##### テスト：正常系

- `item_id` 表で create（PK 未指定）すると返却行の `item_id` が数値で入り、同値で read できる
- create 時に `item_id` を明示しても、その値の行が返る
- `columns` 付き read で `item_id` を投影できる

##### テスト: 異常系

- 空 `cols` / 非オブジェクトは既存どおり拒否する
- 制約違反は SQLite 例外になる

---

#### bun.pkSearchPaging

- offset / cursor いずれの並びも **設定 PK 列の昇順**
- cursor モードの `nextCursor` は生の PK 値（`item_id` 等）
- `paging` 切替・戻り形は #90 節のまま

##### テスト：正常系

- カスタム PK 表で未指定 / `paging: "offset"` のとき `ORDER BY item_id` 相当でページが進む
- `paging: "cursor", limit: 2` で1ページ目の `nextCursor` が最後の `item_id` になり、2ページ目で続きが取れる
- 最終ページで `hasMore === false`、`nextCursor === null`
- 同じクエリで `list` === `search`
- デフォルト `id` 表では #90 節どおり（回帰）

##### テスト: 異常系

- 相反入力（offset↔cursor）は #90 節どおり拒否する
- 不正 `limit` / `paging` / `offset` / `cursor` は既存どおり拒否する

---

#### bun.pkUpsertDuplicateBulk

- `upsert` / `bulkUpsert` の必須キー・conflict 対象は設定 PK
- `duplicate` は設定 PK をコピーせず新しい行を挿入する

##### テスト：正常系

- カスタム PK で未存在の `item_id` を upsert すると挿入され、返却行にその内容が入る
- 既存の `item_id` を upsert すると更新され、未指定カラムは維持される
- duplicate すると新しい `item_id` の行が返り、元行は変わらない。overrides は効く
- bulkUpsert は各行に PK があれば件数どおり処理する

##### テスト: 異常系

- upsert で PK キーが無いとき拒否する（メッセージは設定 PK 向け。例: `upsert requires cols.item_id`）
- bulkUpsert でいずれかの行に PK が無いとき拒否する
- duplicate の where 欠落は既存どおり拒否する
- duplicate 対象0件は `null`（例外にしない）

---

#### bun.pkRegressionDefaultId

- オプション省略時、v0.1〜v0.7 および #90 節の `id` 契約を壊さない

##### テスト：正常系

- `createCrud(db)` で upsert に `cols.id` 必須・duplicate が `id` を剥がす・cursor が `id` 基準、が従来どおり
- `count` / 基本 CRUD / where のスモークが通る

##### テスト: 異常系

- （本版で既存の拒否を緩和しない）

#### gorm.createCrudPk / libsql.createCrudPk

- `CreateCrud(db)` / `CreateCrud(db, crudian.Options{})` / `CreateCrud(db, crudian.Options{PK: "id"})` は `id`
- `CreateCrud(db, crudian.Options{PK: "item_id"})` は `item_id`
- `Transaction` 内の CRUD にも同じ PK 設定が引き継がれる

##### テスト：正常系

- カスタム PK 表で Create が採番行を返す
- Search の offset / cursor が PK 昇順。`NextCursor` が生の PK 値
- Upsert / Duplicate / BulkUpsert がカスタム PK で動く
- オプション省略で従来の `id` 挙動
- `List` === `Search`
- Transaction コールバック内でも同じ PK で読める

##### テスト: 異常系

- `PK: ""` を拒否する
- 指定 PK 列がテーブルに無いとき拒否する（独自エラー）
- Upsert で PK キー欠落を拒否する
- BulkUpsert で行の PK 欠落を拒否する

（gorm / libsql は同等観測。厚いケースはどちらか一方でもよいが、両アダプタでスモークは通す）
