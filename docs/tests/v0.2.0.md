## 共通前提

| 項目 | 値 |
|------|-----|
| 対象パッケージ | `@b4moss/crudian/bun-sqlite` |
| ランタイム / テスト | Bun + `bun:test` |
| DB | 呼び出し側注入の `bun:sqlite` `Database`（テストでは `:memory:`） |
| 入口 | `createCrud(db)`（v0.1.0 で提供済み） |
| upsert / bulkUpsert conflict | 主キー `id` |
| 単発書き込み戻り値 | 対象行（0件は `null`。`upsert` は挿入または更新後の行） |
| bulk 戻り値 | 件数のみ |
| トランザクション | 自動では張らない。必要なら `transaction` を利用 |
| 対象外（本版の自動テスト必須ではない） | Bun テンプレ試し食い（推奨・手動／別 Issue） |

フィクスチャ表（例）は整数主キー `id` を持つ単表とする。スキーマはテスト内 DDL で用意してよい。  
v0.1.0 の CRUD / `search` / 条件ビルダーは回帰として壊さない（本版で触る範囲のスモークでよい）。

## 単発の拡張書き込み

### upsert

- 主キー `id` を conflict 対象として挿入または更新する
- 結果の対象行を返す
- `cols` に `id` が含まれる（更新対象の特定に使う）

#### テスト：正常系

- 未存在の `id`（または新規行）を渡すと挿入され、返却行にその内容が入る
- 既存の `id` を渡すと更新され、返却行は更新後の値になる
- 更新時、未指定カラムの扱いは実装方針どおりで安定している（上書きしない／null 化する等。一方に固定）

#### テスト: 異常系

- テーブル名が文字列でないとき拒否する
- `cols` がオブジェクトでない／空のとき拒否する
- 存在しないテーブル参照は SQLite 例外になる
- NOT NULL 等の制約違反は SQLite 例外になる

---

### duplicate

- 条件に合う1行を複製し、必要なら overrides をマージして挿入する
- 複製後の対象行を返す
- 対象0件のときは `null`

#### テスト：正常系

- 存在する行を duplicate すると新しい `id` の行が返り、元行の値がコピーされる
- overrides で指定したカラムだけ差し替えられる
- 元行は変更されない

#### テスト: 異常系

- 対象0件のとき `null` を返す（例外にしない）
- テーブル名が文字列でないとき拒否する
- where が無い／不正なとき拒否する
- 一意制約に抵触する複製は SQLite 例外になる

---

## bulk 系

いずれも戻り値は件数（number）のみ。自動トランザクションは張らない。

### bulkCreate

- 複数行を挿入し、挿入件数を返す

#### テスト：正常系

- 複数行を渡すと、その件数分挿入され戻り値が一致する
- 空配列は件数 `0` で成功（no-op）
- 挿入後に `search` で行が読める

#### テスト: 異常系

- テーブル名が文字列でないとき拒否する
- 行要素がオブジェクトでないとき拒否する
- 制約違反は SQLite 例外になる（途中失敗時の残存は SQLite / 呼び出し側 TX に従う）
- 存在しないテーブル参照は SQLite 例外になる

---

### bulkUpdate

- 条件に合う複数行を同じ更新内容で更新し、影響件数を返す

#### テスト：正常系

- 複数行にマッチする where で、更新件数と内容が期待どおり
- 対象0件のとき戻り値は `0`
- 更新後に `search` で値が反映されている

#### テスト: 異常系

- where が必須で欠落しているとき拒否する
- テーブル名が文字列でないとき拒否する
- 更新カラムが空のとき拒否する
- 存在しないテーブル参照は SQLite 例外になる

---

### bulkDelete

- 条件に合う複数行を削除し、削除件数を返す

#### テスト：正常系

- 複数行削除で戻り値が件数と一致し、以降読めない
- 対象0件のとき戻り値は `0`
- 一部だけマッチする where で、マッチ分だけ消える

#### テスト: 異常系

- where が必須で欠落しているとき拒否する
- テーブル名が文字列でないとき拒否する
- 存在しないテーブル参照は SQLite 例外になる

---

### bulkUpsert

- 複数行を `id` conflict で upsert し、処理件数を返す

#### テスト：正常系

- 新規のみの配列で挿入件数分が返る
- 既存 id を含む配列で更新され、件数は入力件数と一致する
- 新規と既存が混在しても、それぞれ挿入／更新され件数が一致する
- 空配列は件数 `0` で成功（no-op）

#### テスト: 異常系

- テーブル名が文字列でないとき拒否する
- 行に conflict 用の `id` が必要なのに欠ける場合の扱いが仕様どおり（拒否または SQLite 例外。一方に固定）
- 制約違反は SQLite 例外になる
- 存在しないテーブル参照は SQLite 例外になる

---

## 回帰（スモーク）

v0.1.0 Core を壊していないことの最小確認。

### coreRegression

- 既存の `create` / `read` / `update` / `delete` / `search` が引き続き動作する
- `transaction` ヘルパが引き続き使える

#### テスト：正常系

- `create` → `read` が行を返す
- `search` が `{ items, nextCursor, hasMore }` を返す
- `transaction` 内の書き込みがコミットされる

#### テスト: 異常系

- `read` 未ヒットは引き続き `null`
- `update` 0件は引き続き `null`
