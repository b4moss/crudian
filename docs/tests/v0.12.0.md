## 共通前提

| 項目 | 値 |
|------|-----|
| 対象パッケージ | Packagist **`b4moss/crudian`**（単一。配置 `packages/php/`） |
| 共有 | `B4moss\Crudian\`（Where / Dialect / Executor / Crud / 型・エラー） |
| アダプタ | `B4moss\Crudian\Pdo\`（PDO）、`B4moss\Crudian\Libsql\`（公式 SDK・preview） |
| 契約 | JS bun-sqlite / Go `crudian`+アダプタと同等の語彙・振る舞い |
| ランタイム / テスト | **PHP 8.3+** + PHPUnit。アダプタ固有（共有スイートの強制共有はしない） |
| 入口 | `createCrud($client, ?Options $options = null)`。接続を内部生成しない。生クライアントを公開 |
| メソッド名 | 仕様どおり小文字（`create` / `read` / `update` / `delete` / `search` / `list` / `count` / `exists` / `upsert` / `duplicate` / `bulkCreate` / `bulkUpdate` / `bulkDelete` / `bulkUpsert` / `transaction`） |
| PDO | MySQL / Postgres / SQLite。ORM 不使用。Dialect で方言差を吸収 |
| libSQL | 公式 SDK（`turso/libsql` 等）。**テクニカルプレビュー**。薄い Executor で橋渡し。PDO ではない |
| Executor | `run` / `get` / `all` / `transaction`。共有 Crud は Executor + Dialect のみに依存 |
| upsert / bulkUpsert conflict | 主キー列（デフォルト `id`。`options.pk` で変更可＝#72 同等） |
| 単発書き込み戻り値 | 対象行。`read` / `update` / `duplicate` の0件は行なし（例外にしない） |
| bulk 戻り値 | 件数のみ |
| `search` / `list` | [`./v0.8.0.md`](./v0.8.0.md) どおり。`paging` 未指定 = `"offset"`。cursor 時は PK 昇順 |
| `SearchResult` | offset: `items` / `total` / `offset` / `limit` / `hasMore`。cursor: `items` / `nextCursor` / `hasMore` / `total` |
| `count` | where 全件数。入力は `{ where? }` のみ |
| `exists` | [`./v0.9.0.md`](./v0.9.0.md) どおり。`count > 0` の糖衣。boolean |
| `columns` | `read` / `search` / `list` で投影可。省略は全列 |
| 識別子 / エラー | 文字列必須・形式検証なし。独自エラー最小。他は下位（PDO / SDK）例外 |
| プール | 第一級 API にしない。呼び出し側が PDO 属性等を設定（Go libSQL の no-op に相当） |
| 対象外 | Laravel、リモート Turso Cloud E2E、全文検索、orderBy 一般化、製品 E2E、#128 / #129 |

フィクスチャ表（例）は整数主キー単表。スキーマはテスト内 DDL で用意してよい（方言に合わせる）。  
**同等性の判定:** 同じ操作列に対し、JS / Go 仕様（v0.1〜v0.10 の該当契約）と同じ観測結果になること。  
重複記述を避けるため、後続アダプタ節は「PDO SQLite 節と同等」と書いて実装してよい。

## 共有（`B4moss\Crudian`）

### php.where

- 公開ビルダ: `eq` / `ne` / `lt` / `gt` / `lte` / `gte` / `in` / `like` / `isNull` / `isNotNull`
- nestable `and` / `or`

#### テスト：正常系

- 各演算子が SQL 条件として効く（アダプタ結合経由で観測してよい）
- `and` / `or` のネストが絞り込みに反映される

#### テスト: 異常系

- カラム名が空／非文字列のとき拒否
- `in` に空配列を渡したとき拒否（JS / Go と同じ）

### php.dialect

- `SqliteDialect` / `PostgresDialect` / `MySQLDialect` が [`./v0.10.0.md`](./v0.10.0.md) と同趣旨のフックを提供する
  - `quoteIdent` / `placeholder`（1-based）/ insert 後行取得 / 列記述（PK 存在確認）
- upsert はアプリ層のまま（`ON CONFLICT` / `ON DUPLICATE KEY` は必須としない）
- WHERE + SET + LIMIT/OFFSET 連結時、`$n` 方言では **通し番号** が崩れない

#### テスト：正常系

- Sqlite: 識別子は `"…"`、placeholder は `?`、列記述は `PRAGMA table_info` 相当
- Postgres: 識別子は `"…"`、placeholder は `$n`、insert は `RETURNING *` 相当、列記述は `information_schema` 相当
- MySQL: 識別子は `` `…` ``、placeholder は `?`、insert 後は `LAST_INSERT_ID` + `SELECT`（RETURNING なし）、列記述は `information_schema` 相当
- `ResolveDialect`（または同等）が `sqlite` / `postgres`|`postgresql` / `mysql` を解決する。空は sqlite

#### テスト: 異常系

- 未知の dialect 名は拒否
- 存在しない PK 列の拒否が列記述経由で効く

### php.executor

- インタフェース: `run`（影響件数）/ `get`（0件は null）/ `all` / `transaction`
- 共有 Crud は具象クライアント型を知らない

#### テスト：正常系

- PDO / libSQL の各 Executor がインタフェースを満たし、Crud 経由で契約が通る

#### テスト: 異常系

- （具象側の null 注入拒否はアダプタ節）

## PDO アダプタ（SQLite）

パッケージ: `B4moss\Crudian\Pdo`  
入口: `createCrud(PDO $pdo, ?Options $options = null)`（生 `PDO` を公開）  
Dialect: 既定 Sqlite。`options` で dialect / pk を指定可  
DB: 呼び出し側注入。テストは `:memory:` または一時ファイル

### pdo.createCrud

#### テスト：正常系

- 注入した `PDO` と公開参照が同一
- 全メソッドが呼べる
- SQLite PDO で初期化エラーなく使える

#### テスト: 異常系

- `$pdo === null` 相当（型で防げる場合は静的で可）／未接続相当の拒否方針を README と一致させる

### pdo.transaction

#### テスト：正常系

- コールバック内の複数 `create` がコミットされ、終了後にすべて読める
- コールバックの例外／戻りが伝わる

#### テスト: 異常系

- コールバック失敗でロールバックされ、部分書き込みが残らない
- 各 CRUD は自動では TX を張らない（明示 `transaction` のみ）

### pdo.coreCrud

`create` / `read` / `update` / `delete`

#### テスト：正常系

- `create` が対象行を返し、PK が採番される
- `read` が1件を返す。`columns` で投影できる
- `update` が更新後行を返す。未指定カラムは維持
- `delete` が影響件数を返す

#### テスト: 異常系

- `read` 未ヒットは行なし（例外なし）
- `update` 0件は行なし
- `delete` 0件は `0`
- テーブル名が不正（空など）のとき拒否
- 制約違反は下位（PDO）例外

### pdo.searchList

[`./v0.8.0.md`](./v0.8.0.md) と同等（offset 既定 / cursor 明示 / 相反拒否 / `list` 別名 / `total`）

#### テスト：正常系

- 未指定または `paging: "offset"` で offset 形の戻り（`offset` / `limit` あり、`nextCursor` なし）
- `paging: "cursor"` で cursor 形（`nextCursor` / `hasMore` / `total`。PK 昇順）
- `Items` が PK 昇順。ページングで続きが重複なく取れる
- `list` と `search` が同結果
- `columns` / where 演算子一式が効く
- `total` は where 全件数（limit / offset / cursor 非依存）

#### テスト: 異常系

- `limit` 不正は拒否
- offset モードで `cursor` / cursor モードで `offset` → 拒否
- `in` 空は拒否

### pdo.count / pdo.exists

[`./v0.5.0.md`](./v0.5.0.md) / [`./v0.9.0.md`](./v0.9.0.md) と同等

#### テスト：正常系

- 空表 `count` → `0`、行追加後に件数一致。`where` で絞れる
- 空表 `exists` → `false`、一致あり → `true`。`exists === (count > 0)`
- `where` なしの `exists` は「1行でもあれば true」

#### テスト: 異常系

- テーブル名不正は拒否
- where 由来の拒否が `search` と同じ

### pdo.extendedWrites

`upsert` / `duplicate` / `bulk*`（[`./v0.2.0.md`](./v0.2.0.md) と同等）

#### テスト：正常系

- `upsert`: 未存在 PK は挿入、既存は更新。対象行を返す
- `duplicate`: 新 PK でコピー。overrides 反映。0件は行なし
- `bulkCreate` / `bulkUpdate` / `bulkDelete` / `bulkUpsert` が件数のみ
- 空配列の bulk は `0`

#### テスト: 異常系

- `upsert` / `bulkUpsert` で PK 欠落は拒否
- `duplicate` / `bulkUpdate` / `bulkDelete` で where 欠落は拒否

### pdo.pkOption

[`./v0.8.0.md`](./v0.8.0.md) #72 節と同等

#### テスト：正常系

- `options.pk`（例: `"item_id"`）で conflict / cursor / upsert が当該列を使う
- 省略時は `"id"`

#### テスト: 異常系

- 表に存在しない PK 列名は拒否（列記述経由）

## PDO アダプタ（Postgres / MySQL）

入口・公開 API は SQLite と同じ。`options.dialect`（または DSN から明示）で切替。  
テスト DB: [`docker/compose.yaml`](../../docker/compose.yaml) の Postgres / MySQL（例: `DATABASE_URL_POSTGRES` / `DATABASE_URL_MYSQL`）。資格情報は compose 既定。  
契約: 上記 PDO SQLite 節と **同等観測**（CRUD / where / search・list / count / exists / extended / transaction / pk）。

### pdo.postgres

#### テスト：正常系

- Dialect Postgres で単発 `create` が行を返す（RETURNING 相当）
- `$n` 通し番号が SET + WHERE + LIMIT/OFFSET で崩れない（更新・検索で観測）
- 契約スモーク（core + search offset 1ケース + count + upsert 1ケース）が緑

#### テスト: 異常系

- SQLite 節の異常系と同等（代表ケースでよい）

### pdo.mysql

#### テスト：正常系

- Dialect MySQL で単発 `create` が行を返す（insert 後 SELECT 相当。RETURNING なし）
- 契約スモークが緑（Postgres 節と同趣旨）

#### テスト: 異常系

- SQLite 節の異常系と同等（代表ケースでよい）

CI: サーバ DB が無いジョブでは Postgres / MySQL ケースをスキップしてよい。スキップ方針は README / CI に明記する。SQLite 契約は CI 必須。

## libSQL アダプタ（technical preview）

パッケージ: `B4moss\Crudian\Libsql`  
入口: `createCrud($connection, ?Options $options = null)`（公式 SDK の接続型。生クライアントを公開）  
Dialect: Sqlite（libSQL 互換）  
DB: 一時ファイル（`:memory:` は TX と相性が悪い場合があるためテストではファイル推奨。JS v0.6.0 と同じ）  
制約: SDK / `ext-ffi` 等は **アダプタ境界に閉じる**。共有 Crud に漏らさない

### libsql.createCrud

#### テスト：正常系

- 注入クライアントと公開参照が同一
- 全メソッドが呼べる
- 一時ファイル DB で初期化できる

#### テスト: 異常系

- クライアント未指定相当は拒否

### libsql.contractParity

- PDO SQLite 節の transaction / coreCrud / searchList / count / exists / extendedWrites / pkOption と **同等観測**
- ファイル内で重複記述を避け、「PDO SQLite と同等」と書いて実装してよい

#### テスト：正常系

- PDO SQLite 節の正常系と同等（少なくとも core + search offset + count + exists + upsert + transaction）

#### テスト: 異常系

- PDO SQLite 節の異常系と同等（代表ケース）

### libsql.previewBoundary

#### テスト：正常系

- README に technical preview・FFI / SDK 要件・リモート Cloud E2E 非対象を明記する
- Docker / CI で `ext-ffi` が用意され、libSQL テストが実行できる（または明示的に必須ジョブ化）

#### テスト: 異常系

- （preview API 破壊は upstream 都合。アダプタ修正で吸収し、共有契約を壊さない）
