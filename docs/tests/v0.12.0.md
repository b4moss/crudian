  - `quoteIdent` / `placeholder`（1-based）/ insert 後行取得 / 列記述（PK 存在確認）

- MySQL: 識別子は `` `…` ``、placeholder は `?`、insert 後は `LAST_INSERT_ID` + `SELECT`（RETURNING なし）、列記述は `information_schema` 相当
- `ResolveDialect`（または同等）が `sqlite` / `postgres`|`postgresql` / `mysql` を解決する。空は sqlite

#### テスト: 異常系

- 未知の dialect 名は拒否
- 存在しない PK 列の拒否が列記述経由で効く

### php.executor

- インタフェース: `run`（影響件数）/ `get`（0件は null）/ `all` / `transaction`

# Part B — #139 orderBy（ORDER BY）

## 共通前提（#139）

| 項目 | 値 |
|------|-----|
| 対象（JS） | `@b4moss/crudian/bun-sqlite` / `drizzle` / `prisma` / `libsql` / `typeorm` |
| 対象（Go） | `github.com/b4moss/crudian/go/gorm` / `.../go/libsql`（共有 `go/crudian`） |
| 契約の正 | 共有層の語彙。参照実装の詳細確認は bun-sqlite。他アダプタ・Go は同等観測 |
| 入口 | 既存どおり（JS: `createCrud(db, options?)`、Go: `CreateCrud(db, opts...)`） |
| `SearchQuery` 追加 | `orderBy?: { column: string; direction?: "asc" \| "desc" }[]` |
| 省略時 | 現行どおり **設定中 PK 列 ASC**（非破壊） |
| `direction` 省略 | `"asc"` |
| 識別子 | 文字列必須・形式検証なし。不正時は下位例外（既存どおり） |
| `list` | 引き続き `search` の別名（同じ `SearchQuery`・同じ並び） |
| offset ページング | `orderBy` が効く |
| cursor ページング | **暫定:** `orderBy` が **非空**のとき拒否（下節）。未指定 `orderBy` は現行 PK ASC keyset のまま |
| `count` / `exists` | 契約変更なし（`orderBy` を受け取らない） |
| 対象外（#139 節） | 全文検索、式・生 SQL 断片、NULLS FIRST/LAST、PHP（Part A）、HAVING、JOIN |

フィクスチャ表（例）は整数主キー `id` とソート用列（例: `sort_order` / `name`）を持つ単表。スキーマはテスト内 DDL で用意してよい。  
v0.1〜v0.11 の CRUD / 条件ビルダー / `count` / `exists` / ページング / extended writes は回帰として壊さない。  
**契約追加（非破壊）:** `SearchQuery` に `orderBy` を追加する。未指定時の並び・戻り形は変えない。

### 表記の固定

| 項目 | 決定 |
|------|------|
| 型（JS） | `orderBy?: { column: string; direction?: "asc" \| "desc" }[]` |
| 型（Go） | 同意味（例: `OrderBy []OrderByClause`。公開名は既存 SearchQuery スタイルに合わせる） |
| デフォルト並び | `orderBy` 未指定または空配列 → PK ASC |
| 複数要素 | 配列の先頭から順に ORDER BY に並べる |
| 空配列 | PK ASC と同じ（未指定と同等） |
| 不正 `direction` | `"asc"` / `"desc"` 以外（大文字混在含む）は **拒否**（独自最小エラー） |

### cursor × orderBy（暫定契約）

| 入力 | 期待 |
|------|------|
| `paging: "cursor"` かつ `orderBy` 未指定 / 空 | 現行どおり PK ASC keyset。拒否しない |
| `paging: "cursor"` かつ `orderBy` が1件以上 | **拒否**（独自最小エラー） |
| `paging: "offset"`（または未指定）かつ `orderBy` あり | ソートが効く |

Issue #139 本文の「offset / cursor 双方で効く」とは異なる暫定。PO が案を変えたら本節を差し替える。

## bun-sqlite（参照実装・#139）

ランタイム / テスト: Bun + `bun:test`

### bun.searchOrderByDefault

- SQL イメージ: `… ORDER BY "id" ASC …`（`options.pk` 変更時はその列）

#### テスト：正常系

- `orderBy` なしの cursor `search` が従来どおり PK 昇順 keyset（回帰）
- `orderBy: []`（空配列）も PK ASC と同じ並びになる
- `list` が同じ入力で `search` と同じ並び・同じページ形を返す

#### テスト: 異常系

- （デフォルト経路の新しい拒否は増やさない。既存の不正 `limit` / 相反 paging は従来どおり）

### bun.searchOrderByOffset

- offset（または `paging` 未指定）で `orderBy` が効く
- SQL イメージ: `… ORDER BY "sort_order" ASC, "id" DESC LIMIT ? OFFSET ?` のように指定順

#### テスト：正常系

- 単列 ASC: `orderBy: [{ column: "sort_order" }]`（または `direction: "asc"`）で `sort_order` 昇順になる
- 単列 DESC: `orderBy: [{ column: "sort_order", direction: "desc" }]` で降順になる
- 複数列: 第1キーで並び、同値は第2キーで分かれる（例: `sort_order` ASC + `id` ASC）
- `where` ありでも指定並びが保たれ、`total` は where 全件数のまま（limit/offset 非依存）

- `column` が文字列でないとき拒否する（または既存識別子ルールと同型の拒否）
- `orderBy` が配列でないとき拒否する

# Part C — #136 groupBy / aggregates（GROUP BY）

## 共通前提（#136）

| 項目 | 値 |
|------|-----|
| 対象（JS） | `@b4moss/crudian/bun-sqlite` / `drizzle` / `prisma` / `libsql` / `typeorm` |
| 対象（Go） | `github.com/b4moss/crudian/go/gorm` / `.../go/libsql`（共有 `go/crudian`） |
| 契約の正 | 共有層の語彙。参照実装の詳細確認は bun-sqlite。他アダプタ・Go は同等観測 |
| 入口 | 既存どおり |
| `SearchQuery` 追加 | `groupBy?: string[]` と `aggregates?: { fn; column?; as }[]` |
| `aggregates.fn` | `"count"` \| `"sum"` \| `"avg"` \| `"min"` \| `"max"` |
| `aggregates.column` | `count` 以外は必須。`count` で省略時は `COUNT(*)` |
| `aggregates.as` | 結果行のキー（必須） |
| 省略時 | `GROUP BY` なし（現行の行一覧 SELECT） |
| `columns` | グループキー等の投影（既存どおり識別子）。集約は `aggregates` 側 |
| ページング | **offset のみ**。`paging: "cursor"` との併用は拒否 |
| `total` | **グループ件数**（where 適用後。limit / offset 非依存） |
| `orderBy` 併用 | 可。未指定かつ `groupBy` ありのときは **先頭グループ列 ASC** |
| `list` | 引き続き `search` の別名 |
| `count` / `exists` | 本版では `groupBy` / `aggregates` を受け取らない（載せない） |
| 対象外（#136 節） | HAVING、式・生 SQL、JOIN / 複数表、PHP（Part A）、全文検索 |

フィクスチャ表（例）: `id` PK、`album_id`（グループキー）、`score`（数値集約用）など。テスト内 DDL でよい。  
**契約追加（非破壊）:** `groupBy` / `aggregates` 未指定時は現行 `search` と同じ。  
依存: Part B（#139）の `orderBy`（デフォルト並び・併用ケース）。未実装なら当該ケースはブロック。

### 表記の固定

| 項目 | 決定 |
|------|------|
| `groupBy` | 列名文字列の配列。順序が SQL `GROUP BY` の順序 |
| 空 `groupBy`（`[]`） | **拒否** |
| `aggregates` 省略 | `groupBy` のみ可（集約なし。投影は `columns`） |
| `aggregates` のみ（`groupBy` なし） | **暫定:** 拒否（グループキー無しの全体集約は v0.12 非目標） |
| 不正 `fn` | 拒否 |
| `as` 欠落 / 空文字 | 拒否 |
| `sum`/`avg`/`min`/`max` で `column` 欠落 | 拒否 |
| 集約結果の型 | 観測は「数値として比較できる」程度（方言差の厳密型は固定しない） |
