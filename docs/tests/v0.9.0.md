# Part A — #106 exists / Exists

## 共通前提（#106）

| 項目 | 値 |
|------|-----|
| 対象（JS） | `@b4moss/crudian/bun-sqlite` / `drizzle` / `prisma` / `libsql` |
| 対象（Go） | `github.com/b4moss/crudian/go/gorm` / `.../go/libsql`（共有 `go/crudian`） |
| 契約の正 | 共有層の語彙。参照実装の詳細確認は bun-sqlite。他アダプタ・Go は同等観測 |
| 入口 | 既存どおり（JS: `createCrud(db)`、Go: `CreateCrud(db)`） |
| 名前 | JS: `exists` / Go: `Exists`（`duplicate`／`Duplicate`＝行コピーと混同しない） |
| 入力 | `count` / `Count` と同型。JS 第2引数は既存 `CountQuery`（`{ where? }`）。Go は `ExistsQuery`（`Where` のみ） |
| 戻り値 | JS: `boolean`（async アダプタは `Promise<boolean>`）。Go: `(bool, error)` |
| 意味 | 条件に一致する行が **1件以上あるか**。件数は返さない |
| 糖衣関係 | `exists(...) === count(...) > 0`（Go は `Exists` ⇔ `Count > 0`）。実装は短絡可 |
| SQL イメージ | `SELECT 1 … FROM table [WHERE …] LIMIT 1`（当面 `COUNT(*) > 0` でも観測契約は同じ） |
| where コンパイル | `count` / `search` と同じ経路を流用する（別方言を増やさない） |
| `columns` / `limit` / `cursor` / `offset` | 受け取らない（`count` と同じ） |
| 識別子 / エラー | 既存どおり（文字列必須・形式検証なし。独自エラー最小。他は下位例外） |
| 対象外（#106 節） | メール／アカウント専用 API、HTTP 公開方針、ドメインエラー型、PHP、Dialect / MySQL・Postgres（#73） |

フィクスチャ表（例）は整数主キー `id` を持つ単表。スキーマはテスト内 DDL で用意してよい。  
既存登録チェック相当の where（例: `eq("email", …)` / `Eq("email", …)`）を少なくとも1ケース含める。  
v0.1〜v0.8 の CRUD / 条件ビルダー / `count` / ページング / extended writes は回帰として壊さない。  
**契約追加（非破壊）:** Facade に `exists` / `Exists` を追加する。既存メソッドのシグネチャは変えない。

### 使い分け（ドキュメント・README にも一行）

| 欲しいもの | API |
|------------|-----|
| 存在の有無だけ | `exists` / `Exists` |
| 件数 | `count` / `Count` |

## bun-sqlite（参照実装）

パッケージ: `@b4moss/crudian/bun-sqlite`  
ランタイム / テスト: Bun + `bun:test`  
DB: 呼び出し側注入の `bun:sqlite` `Database`（テストでは `:memory:`）

### bun.exists

- 条件に合う行があるかを boolean だけで返す
- SQL イメージ: `SELECT 1 FROM table [WHERE ...] LIMIT 1`
- `where` なしは「テーブルに1行でもあれば true」
- `where` ありは `search` / `count` と同じ条件集合の存在判定
- `count(table, query) > 0` と同値

#### テスト：正常系

- 空表で `exists(table)` が `false` を返す
- 1行以上挿入したあと `exists(table)` が `true` を返す
- `where` ありで一致するとき `true`（例: `eq("email", "a@example.com")`）
- `where` ありで一致0件のとき `false`（throw しない）
- 同じ `where` について `exists(...) === (count(...) > 0)` が常に成り立つ
- Facade に `exists` が関数として存在する

#### テスト: 異常系

- テーブル名が文字列でないとき拒否する（`count` と同じ）
- 存在しないテーブル参照は SQLite 例外になる
- `in` に空配列を渡したときの扱いが `count` / `search` と同じ（拒否または0件相当。一方に固定）
- カラム名が文字列でないとき（where 経由）は `count` / `search` と同じ拒否になる

# Part B — #105 DB 接続プール／接続維持時間（Go/GORM 先行）

## 共通前提（#105）

| 項目 | 値 |
|------|-----|
| 対象（必須） | Go `github.com/b4moss/crudian/go/gorm`（共有 `go/crudian`） |
| 対象（no-op 観測） | Go `.../go/libsql` |
| 対象外（本節） | JS 全アダプタ（→ [#73](https://github.com/b4moss/crudian/issues/73) / [`./v0.10.0.md`](./v0.10.0.md)）、PHP、接続 URL オープン、env からの秘密情報、Dialect インタフェース |
| 所有 | 接続の生成・所有は呼び出し側。`CreateCrud` は接続を開かない（既存方針） |
| 型 | `crudian.PoolOptions`（仮称確定名: `PoolOptions`） |
| 入口 | （1）`crudian.ApplyPool(*sql.DB, *PoolOptions)` ヘルパ（2）`crudian.Options{Pool: ...}` を `CreateCrud` に渡す |
| フィールド | すべてポインタ。`MaxOpenConns *int` / `MaxIdleConns *int` / `ConnMaxLifetime *time.Duration` / `ConnMaxIdleTime *time.Duration` |
| 未指定 | フィールドが `nil`、または `Options.Pool == nil` → その項目／全体を触らない（ドライバ／ランタイム既定のまま） |
| GORM 適用 | `CreateCrud` 時に `Pool != nil` なら `db.DB()` で `*sql.DB` を取り、`ApplyPool` する |
| libSQL | `Options.Pool` を受け取っても **適用しない**（エラーにしない／無視）。ドキュメントとテストで明示 |
| Dialect | プール設定を Dialect に載せない（接続ライフサイクルは別関心） |
| CRUD 契約 | `create` / `search` 等のメソッド面にプール引数を常設しない |

適用時に呼ぶ `database/sql` API（非 nil 項目のみ）:

- `SetMaxOpenConns`
- `SetMaxIdleConns`
- `SetConnMaxLifetime`
- `SetConnMaxIdleTime`

**契約追加（非破壊）:** `Options` に任意の `Pool` を足す。未指定時の既存挙動は変えない。

### 使い分け（README にも一行）

| 欲しいもの | 手段 |
|------------|------|
| GORM でプールを載せたい | `CreateCrud(db, crudian.Options{Pool: &PoolOptions{...}})` |
| 既に持っている `*sql.DB` に載せたい | `crudian.ApplyPool(db, &PoolOptions{...})` |
| libSQL / SQLite 単一接続 | Pool を渡さなくてよい（渡しても no-op） |

---

## crudian.ApplyPool（共有ヘルパ）

パッケージ: `github.com/b4moss/crudian/go/crudian`  
対象: 任意の `*sql.DB`

### crudian.applyPool

- `*sql.DB` にプール／lifetime を選択適用する
- `p == nil` は no-op（成功）
- `db == nil` は拒否

#### テスト：正常系

- `MaxOpenConns` のみ指定 → 当該 setter のみ適用（例: 適用後 `db.Stats().MaxOpenConnections` が指定値）
- 複数フィールドを同時指定 → 指定分だけ適用される
- `p == nil` でエラーなく、既存設定を変えない

#### テスト: 異常系

- `db == nil` のときエラーを返す

## Go gorm（適用あり）

パッケージ: `github.com/b4moss/crudian/go/gorm`  
入口: `CreateCrud(db *gorm.DB, opts ...crudian.Options)`  
ランタイム / テスト: Go `testing` + SQLite（既存フィクスチャ）

### gorm.poolOptions

- `Options{Pool: ...}` 付き `CreateCrud` で底层 `*sql.DB` にプール／lifetime が載る
- `db.DB()` 失敗時は `CreateCrud` がエラーを返す
- `Pool == nil`（または Options 省略）のときは既存どおり何も触らない
- 適用後も通常の CRUD（create / read / count 等）が動く

#### テスト：正常系

- `Pool` なしの `CreateCrud` が従来どおり成功する（回帰）
- `MaxOpenConns` を指定して `CreateCrud` → `crud.DB.DB()` 経由の `Stats().MaxOpenConnections` が一致する
- `MaxIdleConns` / `ConnMaxLifetime` / `ConnMaxIdleTime` を指定しても `CreateCrud` が成功し、その後の CRUD スモークが通る
- `PK` と `Pool` を同時に渡せる（例: `Options{PK: "id", Pool: ...}`）

#### テスト: 異常系

- （`db == nil` の既存拒否は維持）
- `Pool` 適用経路で底层 DB 取得に失敗した場合はエラー（実装が再現できる範囲で）

## Go libsql（no-op）

パッケージ: `github.com/b4moss/crudian/go/libsql`  
入口: `CreateCrud(db *sql.DB, opts ...crudian.Options)`

### libsql.poolNoop

- `Options{Pool: ...}` を渡しても **プール設定を適用しない**
- エラーにせず `CreateCrud` は成功する
- 既存 CRUD 契約は壊さない

#### テスト：正常系

- `Pool` 付き `CreateCrud` が成功する
- 適用前後で呼び出し側が観察できる範囲において、ライブラリが `SetMax*` 相当を強制しない（no-op であること）。少なくとも「`Pool` を渡しても Create / Count が通る」ことを担保する
- `Pool` なしの既存テストが引き続き緑であること（回帰）

#### テスト: 異常系

- `db == nil` の既存拒否は維持（`Pool` の有無で緩和しない）
