## 共通前提

| 項目 | 値 |
|------|-----|
| 対象（JS） | `@b4moss/crudian/bun-sqlite` / `drizzle` / `prisma` / `libsql` |
| 対象（Go） | `github.com/b4moss/crudian/go/gorm` / `.../go/libsql`（共有 `go/crudian`） |
| 契約の正 | 共有層の語彙。参照実装の詳細確認は bun-sqlite。他アダプタ・Go は同等観測 |
| 入口 | 既存どおり（JS: `createCrud(db)`、Go: `CreateCrud(db)`） |
| 名前 | JS: `exists` / Go: `Exists`（`duplicate`／`Duplicate`＝行コピーと混同しない） |
| 入力 | `count` / `Count` と同型。JS 第2引数は既存 `CountQuery`（`{ where? }`）。Go は `ExistsQuery`（`Where` のみ） |
| 戻り値 | JS: `boolean`（async アダプタは `Promise<boolean>`）。Go: `(bool, error)` |
| 意味 | 条件に一致する行が **1件以上あるか**。件数は返さない |
| 糖衣関係 | `exists(...) === count(...) > 0`（Go は `Exists` ⇔ `Count > 0`）。実装は短絡可 |
| SQL イメージ | `SELECT 1 … FROM table [WHERE …] LIMIT 1`（当面 `COUNT(*) > 0` でも観測契約は同じ） |
| where コンパイル | `count` / `search` と同じ経路を流用する（別方言を増やさない） |
| `columns` / `limit` / `cursor` / `offset` | 受け取らない（`count` と同じ） |
| 識別子 / エラー | 既存どおり（文字列必須・形式検証なし。独自エラー最小。他は下位例外） |
| 対象外（本ファイル） | #105、メール／アカウント専用 API、HTTP 公開方針、ドメインエラー型、PHP、Dialect / MySQL・Postgres（#73） |

フィクスチャ表（例）は整数主キー `id` を持つ単表。スキーマはテスト内 DDL で用意してよい。  
既存登録チェック相当の where（例: `eq("email", …)` / `Eq("email", …)`）を少なくとも1ケース含める。  
v0.1〜v0.8 の CRUD / 条件ビルダー / `count` / ページング / extended writes は回帰として壊さない。  
**契約追加（非破壊）:** Facade に `exists` / `Exists` を追加する。既存メソッドのシグネチャは変えない。

### 使い分け（ドキュメント・README にも一行）

| 欲しいもの | API |
|------------|-----|
| 存在の有無だけ | `exists` / `Exists` |
| 件数 | `count` / `Count` |

## bun-sqlite（参照実装）

パッケージ: `@b4moss/crudian/bun-sqlite`  
ランタイム / テスト: Bun + `bun:test`  
DB: 呼び出し側注入の `bun:sqlite` `Database`（テストでは `:memory:`）

### bun.exists

- 条件に合う行があるかを boolean だけで返す
- SQL イメージ: `SELECT 1 FROM table [WHERE ...] LIMIT 1`
- `where` なしは「テーブルに1行でもあれば true」
- `where` ありは `search` / `count` と同じ条件集合の存在判定
- `count(table, query) > 0` と同値

#### テスト：正常系

- 空表で `exists(table)` が `false` を返す
- 1行以上挿入したあと `exists(table)` が `true` を返す
- `where` ありで一致するとき `true`（例: `eq("email", "a@example.com")`）
- `where` ありで一致0件のとき `false`（throw しない）
- 同じ `where` について `exists(...) === (count(...) > 0)` が常に成り立つ
- Facade に `exists` が関数として存在する

#### テスト: 異常系

- テーブル名が文字列でないとき拒否する（`count` と同じ）
- 存在しないテーブル参照は SQLite 例外になる
- `in` に空配列を渡したときの扱いが `count` / `search` と同じ（拒否または0件相当。一方に固定）
- カラム名が文字列でないとき（where 経由）は `count` / `search` と同じ拒否になる

## 回帰（スモーク）

### regressionAfterExists

- v0.1〜v0.8 の振る舞いを壊さない（Facade に `exists` / `Exists` が増えたこと以外）
- `count` / `Count` の契約は変更しない

#### テスト：正常系

- `create` → `read` が行を返す
- `count` / `Count` が従来どおり件数を返す
- `search` / `list` のページング（offset / cursor）スモークが通る
- `upsert` / `bulkCreate` など既存 extended のスモークが通る（触る範囲でよい）

#### テスト: 異常系

- `read` 未ヒットは引き続き `null` / 行なし
- 不正 `limit` / 空 `in` は引き続き拒否
