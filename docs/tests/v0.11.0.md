# Part A — #43 TypeORM adapter

## 共通前提（#43）

| 項目 | 値 |
|------|-----|
| パッケージ | `@b4moss/crudian/typeorm` |
| ソース | `packages/js/src/typeorm/` |
| peer | `typeorm`（optional） |
| 入口 | `createCrud(dataSource, options?)` |
| 注入 | **`DataSource` のみ**。接続生成・`initialize`・entities / migrations / pool は呼び出し側 |
| 表の指定 | 公開 API は **表名文字列** が第一級。Entity クラスを第一引数にする API は初版対象外 |
| 生 DB | `crud.db` に注入した `DataSource` を公開（JOIN・QueryBuilder 直叩き等） |
| 共有層 | 既存 `createAsyncCrud` + `resolveDialect`。アダプタ内に方言 SQL を再発明しない |
| Dialect 解決 | `DataSource.options.type` から既定選択（`sqlite` / `better-sqlite3` → sqlite、`postgres` → postgres、`mysql` / `mariadb` → mysql）。`options.dialect` で上書き可 |
| TypeORM 利用 | QueryRunner で TX、実行は共有 CRUD が生成する SQL を `query` 経由。Entity / Repository は補助（メタデータ等）に留めてよい |
| 契約の正 | v0.1〜v0.10 と同等の async 観測（CRUD / where / search・list / count / exists / upsert・duplicate・bulk* / transaction / 可変 PK） |
| ランタイム | **Node.js 24+** と **Bun** の両方で必須 |
| DB（初版必須） | **SQLite + Postgres + MySQL** |
| プール | DataSource オプション側。Dialect に載せない（[`./v0.10.0.md`](./v0.10.0.md) Part D と同趣旨） |
| upsert | アプリ層のまま（read → update / create） |
| 対象外 | Entity 第一級 API、関係グラフ横断 CRUD、Cloud 専用 E2E、PHP、Dialect の TypeORM 内再実装 |

フィクスチャ表（例）は整数主キーを持つ単表。スキーマはテスト内 DDL で用意する。  
Postgres / MySQL は [`docker/compose.yaml`](../../docker/compose.yaml)（例: `DATABASE_URL_POSTGRES` / `DATABASE_URL_MYSQL`）。未設定時はサーバ方言スイートを **skip** してよい（Prisma と同趣旨）。  
MariaDB は必須対象としない（`mariadb` type は mysql dialect へマップしてよい）。

### 使い分け（README にも一行）

| 欲しいもの | 手段 |
|------------|------|
| 単表 CRUD | `createCrud(dataSource)` + 表名文字列 |
| JOIN / 関係グラフ | `crud.db`（生 `DataSource` / QueryBuilder） |
| プール | DataSource の接続オプション（呼び出し側） |

## SQLite 契約（常時）

ランタイム: Node 24+（`node:test` / `tsx --test`）**および** Bun（`bun:test` または同等）  
DB: TypeORM が扱える SQLite（例: `:memory:` / 一時ファイル）。ドライバはテストが選ぶ  
入口: `createCrud(dataSource)`（既定 dialect = sqlite）

### typeorm.sqlite.contract

- 初期化済み `DataSource` を渡すと Facade が得られる
- async CRUD 面が一式存在する

#### テスト：正常系

- `create` / `read` / `update` / `delete` が通る（create は挿入行を返す）
- `search` / `list`（offset / cursor）/ `count` / `exists` が既存契約と同趣旨
- `upsert` / `duplicate` / `bulkCreate` / `bulkUpdate` / `bulkDelete` / `bulkUpsert` がアプリ層経路で同趣旨
- `transaction` のコミット／ロールバックが観測できる（QueryRunner / `dataSource.transaction` 経由）
- 可変 PK（`options.pk`）が動く
- `crud.db` が注入した `DataSource` と同一参照である
- Facade に既存 async メソッドが関数として存在する

#### テスト: 異常系

- テーブル名が文字列でないとき拒否する
- 空 `in` 等 where 由来の拒否が既存契約どおり
- 存在しない PK 列の拒否
- 未対応の `options.dialect` 文字列は拒否（`resolveDialect` と同趣旨）
- 未初期化 DataSource での実行失敗は下位（TypeORM）例外でよい（ライブラリが独自に握りつぶさない）
