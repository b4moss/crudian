## 共通前提

| 項目 | 値 |
|------|-----|
| 対象 | `github.com/b4moss/crudian/go/gorm` / `github.com/b4moss/crudian/go/libsql` |
| 共有 | `github.com/b4moss/crudian/go/crudian`（型・`Where`・Dialect・CRUD） |
| 契約 | JS bun-sqlite / prisma / libsql と同等の語彙・振る舞い |
| ランタイム / テスト | **Go 1.26** + `testing`。アダプタ固有（共有スイートの強制共有はしない） |
| DB | 呼び出し側が接続を注入。テストは一時ファイル SQLite（または TX 安全な `:memory:`）。クラウド資格情報不要 |
| 入口 | `CreateCrud(db)`。パスや接続を内部生成しない |
| upsert / bulkUpsert conflict | 主キー列名 `id` |
| 単発書き込み戻り値 | 対象行。`Read` / `Update` / `Duplicate` の0件は行なし（error にしない） |
| bulk 戻り値 | 件数のみ |
| `SearchResult` | `Items`, `NextCursor`, `HasMore`, `Total` |
| `Count` | where 全件数。`CountQuery` は where のみ |
| cursor | 当面 `id` 昇順。`NextCursor` は生の `id` |
| `columns` | `Read` / `Search` / `List` で投影可。省略は全列 |
| 識別子 / エラー | 文字列必須・形式検証なし。独自エラー最小。他は下位例外 |
| 対象外 | GORM の PG/MySQL（**v0.7.0 未実装・将来対応**）、可変 PK（#72）、リモート Turso Cloud E2E、PHP、offset、全文検索 |

フィクスチャ表（例）は整数主キー `id` を持つ単表。スキーマはテスト内 DDL で用意してよい。  
**同等性の判定:** 同じ操作列に対し、JS 仕様（v0.1 / v0.2 / v0.5）と同じ観測結果になること。

## GORM アダプタ（SQLite）

パッケージ: `github.com/b4moss/crudian/go/gorm`  
入口: `CreateCrud(db *gorm.DB)`（生 DB を公開）  
Dialect: Sqlite

### gorm.createCrud

#### テスト：正常系

- 注入した `*gorm.DB` と公開参照が同一
- 全メソッド（Create/Read/Update/Delete/Search/List/Count/Upsert/Duplicate/Bulk*/Transaction）が呼べる
- SQLite 接続を渡して初期化エラーなく使える

#### テスト: 異常系

- `db == nil` のとき拒否する

### gorm.transaction

#### テスト：正常系

- コールバック内の複数 Create がコミットされ、終了後にすべて読める
- コールバックの戻り値（error）が伝わる

#### テスト: 異常系

- コールバックが error を返すとロールバックされ、部分書き込みが残らない
- 各 CRUD は自動では TX を張らない（明示 `Transaction` のみ）

### gorm.coreCrud

`Create` / `Read` / `Update` / `Delete`

#### テスト：正常系

- `Create` が対象行を返し、`id` が採番される
- `Read` が1件を返す。`columns` で投影できる
- `Update` が更新後行を返す。未指定カラムは維持
- `Delete` が影響件数を返す

#### テスト: 異常系

- `Read` 未ヒットは行なし（error なし）
- `Update` 0件は行なし
- `Delete` 0件は `0`
- テーブル名が不正（空など）のとき拒否
- 制約違反は下位例外

### gorm.searchList

`Search`（正式）/ `List`（別名）、条件、cursor、`Total`

#### テスト：正常系

- `Items` が `id` 昇順
- `limit` 未満で `HasMore=false`、`NextCursor=null`
- ページングで続きが重複なく取れる
- `List` と `Search` が同結果（`Total` 込み）
- `columns` 指定で投影される
- `Eq` / `And` / `Or` / 比較 / `In` / `Like` / `IsNull` / `IsNotNull` が絞り込める
- `Total` は where 全件数（limit / cursor 非依存）

#### テスト: 異常系

- `limit` 不正は拒否
- `In` 空は拒否

### gorm.count

#### テスト：正常系

- 空表で `0`
- 複数行後に行数一致
- `where` ありで一致件数のみ

#### テスト: 異常系

- テーブル名不正は拒否
- `In` 空など where 由来の拒否が `Search` と同じ

### gorm.extendedWrites

`Upsert` / `Duplicate` / `Bulk*`

#### テスト：正常系

- `Upsert`: 未存在 id は挿入、既存 id は更新
- `Duplicate`: 新 id でコピー。overrides 反映。0件は行なし
- `BulkCreate` / `BulkUpdate` / `BulkDelete` / `BulkUpsert` が件数のみ
- 空スライスの bulk は `0`

#### テスト: 異常系

- `Upsert` / `BulkUpsert` で `id` 欠落は拒否
- `Duplicate` / `BulkUpdate` / `BulkDelete` で where 欠落は拒否
