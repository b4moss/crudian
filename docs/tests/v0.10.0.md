# Part A — Dialect 切り出しと SqliteDialect 移行

## 共通前提（Dialect）

| 項目 | 値 |
|------|-----|
| 対象（JS） | 共有層（`dialect` + 旧 `sqlite/*` CRUD）および全既存アダプタ（bun-sqlite / drizzle / prisma / libsql） |
| 対象（Go） | `go/crudian` Dialect・CRUD、`go/gorm` / `go/libsql` |
| 契約の正 | 既存 CRUD 語彙・観測結果は **不変**。方言だけを注入可能にする |
| Dialect 必須フック | `quoteIdent` / `placeholder(i)`（1-based）/ insert 後の行取得（`insertReturning` または `fetchAfterInsert`）/ 列記述（PK 存在確認用。旧 `PRAGMA table_info` 相当） |
| Dialect に載せない | 接続プール／lifetime（#105。接続ライフサイクルは別関心） |
| upsert | **アプリ層のまま**（read → update / create）。本版で `ON CONFLICT` / `ON DUPLICATE KEY` SQL フックは必須としない |
| プレースホルダ合成 | WHERE + SET + LIMIT/OFFSET を連結するとき、番号付き方言（`$n`）では **通し番号** が崩れないこと |
| 公開 API | JS: 既存 `createCrud(client, options?)` を維持。Go: 既存 `CreateCrud` を維持。契約語彙の破壊的変更なし |
| 対象外（本 Part） | TypeORM（#43）、PHP、Drizzle の Postgres/MySQL subpath（本マイルストーンでは Prisma で PG/MySQL を充足） |

**同等性:** SqliteDialect 移行後、既存 SQLite アダプタのテスト（v0.1〜v0.9 相当）が緑のままであること。

---

## JS 共有 Dialect

パッケージ: `@b4moss/crudian`（内部モジュール。公開 root に Dialect を必須公開しなくてよい）  
配置イメージ: `packages/js/src/dialect/`（型 + `sqlite` / 後続 `postgres` / `mysql`）

### js.dialect.sqlite

- `SqliteDialect` が現行 SQLite SQL と同趣旨の quote / placeholder / insert 戦略 / 列記述を提供する
- sync create 経路は従来どおり insert 後に行を取得してよい（`last_insert_rowid` 相当）
- async create 経路は従来どおり `RETURNING *` 相当でよい
- `compileWhere` および CRUD SQL 生成は dialect 経由（ハードコードの `"…"` / `?` / `PRAGMA` を共有 CRUD から除去）

#### テスト：正常系

- SqliteDialect の `quoteIdent` が二重引用符で識別子を囲む（内部に `"` があるとき二重化）
- `placeholder(i)` が常に `?` を返す（番号は無視してよい）
- 既存 bun-sqlite / drizzle / prisma(sqlite) / libsql の契約スイートが緑（回帰）
- `create` が行オブジェクトを返す（sync / async それぞれの従来経路）
- `ensurePK` / PK ガードが列記述フック経由でも従来どおり動く

#### テスト: 異常系

- 識別子が文字列でないときの拒否は既存どおり
- 存在しない PK 列を指定したときの拒否は既存どおり（列記述結果に基づく）

# Part B — PostgresDialect

## 共通前提（Postgres）

| 項目 | 値 |
|------|-----|
| 識別子 | 二重引用符 `"x"`（内部 `"` は二重化） |
| プレースホルダ | `$1`, `$2`, …（1-based・通し番号） |
| insert 後 | `RETURNING *` で行を返す（単発 create） |
| 列記述 | `information_schema`（または同等）で PK 列の存在を確認できること |
| JS 必須 ORM | **Prisma**（`options.dialect: "postgres"`。既定は `"sqlite"` のまま） |
| Go 必須 | GORM + Postgres ドライバ。dialect は **明示オプション優先**（誤検出回避） |
| テスト DB | [`docker/compose.yaml`](../../docker/compose.yaml) の Postgres（例: `DATABASE_URL_POSTGRES`）。資格情報は compose 既定 |
| フィクスチャ | 整数主キー単表。DDL は方言に合わせる（例: `SERIAL` / `GENERATED …`）。スキーマはテスト内で用意 |
| 契約 | v0.1〜v0.9 と同等の観測（CRUD / where / search・list / count / exists / upsert・duplicate・bulk* / transaction / 可変 PK） |
| 本 Part の対象外 | Drizzle Postgres subpath、PHP、TypeORM |

## JS PostgresDialect + Prisma

パッケージ: `@b4moss/crudian/prisma`  
ランタイム / テスト: Node.js 24+ + `node:test`（現行スクリプトに従う）  
入口: `createCrud(client, { pk?, dialect?: "sqlite" | "postgres" | "mysql" })`  
既定: `dialect` 省略時は `"sqlite"`（既存テストを壊さない）

### prisma.postgres.dialect

- `PostgresDialect` が `$n` / `"ident"` / `RETURNING *` / 列記述を提供する
- executor は現行の raw Unsafe を維持し、生成 SQL の placeholder 様式だけを dialect に合わせる

#### テスト：正常系

- `dialect: "postgres"` で `createCrud` が初期化できる
- `create` が挿入行を返す（RETURNING 相当）
- `read` / `update` / `delete` が SQLite 契約と同趣旨
- `search` / `list`（offset / cursor）/ `count` / `exists` が同趣旨
- `upsert` / `duplicate` / `bulk*` がアプリ層経路で同趣旨
- `transaction` のコミット／ロールバックが観測できる
- 可変 PK（`pk: "item_id"` 等）が Postgres 上でも動く
- `dialect` 省略時は従来の SQLite テストが緑（回帰）

#### テスト: 異常系

- テーブル名が文字列でないとき拒否
- 空 `in` 等 where 由来の拒否が既存契約どおり
- 存在しない PK 列の拒否
- （任意）未対応の `dialect` 文字列は拒否

# Part D — JS 接続プール／lifetime（#105 連動）

## 共通前提（JS プール）

| 項目 | 値 |
|------|-----|
| 対象 | MySQL / Postgres 向け JS 経路（本版は **Prisma**） |
| 所有 | 接続の生成・所有は呼び出し側（既存方針） |
| Dialect | プール設定を Dialect に載せない |
| SQLite / libSQL / bun-sqlite / drizzle(sqlite) | プール設定の適用は **不要（no-op 可）**。渡してもエラーにしない／無視してよい |
| Go | [`./v0.9.0.md`](./v0.9.0.md) Part B 済み。本 Part でやり直さない |
| 手段 | （A）Prisma datasource / クライアント生成側のプール設定手順を **ドキュメント化**する、および／または（B）将来ドライバ向けの薄い型／ヘルパ。Prisma では **呼び出し側設定が本体** |
| CRUD 契約 | `create` / `search` 等にプール引数を常設しない |

### 使い分け（README にも一行）

| 欲しいもの | 手段 |
|------------|------|
| Prisma + PG/MySQL でプールを載せたい | 呼び出し側の Prisma / ドライバ設定（文書化した手順に従う） |
| Go GORM | `Options.Pool` / `ApplyPool`（v0.9.0） |
| SQLite 系 | 設定不要（no-op） |

## 回帰（スモーク・#73）

### regressionAfterDialect

- upsert は引き続きアプリ層で動く（SQL upsert 必須化で既存を壊さない）

#### テスト：正常系

- 全既存 SQLite アダプタ（JS + Go）のテスト緑
- Postgres / MySQL で create → read → count / exists → search スモーク
- Go: Pool なし / あり（GORM・サーバ DB）で CRUD スモーク

#### テスト: 異常系

- 既存の入力検証（空 table、空 `in` / `In`、相反 paging 入力等）は緩和しない
