## 共通前提

| 項目 | 値 |
|------|-----|
| 対象パッケージ | `@b4moss/crudian/bun-sqlite` |
| ランタイム / テスト | Bun + `bun:test` |
| DB | 呼び出し側注入の `bun:sqlite` `Database`（テストでは `:memory:`） |
| 入口 | `createCrud(db)` |
| 行型 | ジェネリクス |
| 識別子 | 文字列必須。形式検証はしない（不正時は SQLite 例外） |
| 独自エラー | 最小限。他は SQLite 例外を伝播 |
| 対象外（本版） | `upsert` / `duplicate` / `bulk*`（v0.2.0） |

フィクスチャ表（例）は整数主キー `id` を持つ単表とする。スキーマはテスト内 DDL で用意してよい。

## 入口・ヘルパ

### createCrud

- 呼び出し側の `Database` を受け取り、CRUD Facade を返す
- 生の `Database` を公開する（JOIN 等の非 CRUD 用）
- パスや `:memory:` を内部生成しない

#### テスト：正常系

- 注入した `Database` と同じ参照が Facade から読める
- 返却オブジェクトに `create` / `read` / `update` / `delete` / `search` / `list` / `transaction` がある
- `:memory:` の DB を渡しても初期化エラーなく使える

#### テスト: 異常系

- `db` が `null` / `undefined` のとき拒否する（独自最小エラーまたは TypeError）
- `db` が文字列など `Database` 以外のとき拒否する
- Node から本モジュールを読み込んだとき、「誤って import していませんか？」と分かる明示エラーになる

---

### transaction

- コールバックをトランザクション内で実行するヘルパを提供する
- ライブラリの各 CRUD メソッドは自動ではトランザクションを張らない
- 成功時はコミット、コールバック例外時はロールバックする

#### テスト：正常系

- コールバック内の複数 `create` が同一トランザクションでコミットされ、終了後にすべて読める
- コールバックの戻り値が `transaction` の戻り値として伝わる
- ネストせず単一 TX として、一連の書き込みが見える

#### テスト: 異常系

- コールバックが throw したとき変更がロールバックされ、部分書き込みが残らない
- コールバック外（TX なし）の単発 `create` は、他操作の失敗と独立してコミットされる（自動 TX なしの確認）
- コールバックに非関数を渡すと拒否する

## 基本 CRUD

### create

- 指定テーブルへ1行挿入する
- 挿入後の対象行を返す

#### テスト：正常系

- 必須カラムを渡すと行が返り、`id` が採番されている
- 返却行の値が投入値と一致する
- `read` で同じ `id` を読むと同等の行が得られる

#### テスト: 異常系

- テーブル名が文字列でないとき拒否する
- 存在しないテーブルへの挿入は SQLite 例外になる
- NOT NULL 制約違反は SQLite 例外になる
- 一意制約違反は SQLite 例外になる

---

### read

- 条件に合う1行を返す
- 未ヒットは `null`（throw しない）

#### テスト：正常系

- 存在する `id` で行が返る
- 取得カラムを制限できる場合、指定カラムのみ（または仕様どおり）返る
- 複数行にマッチし得る条件でも1行だけ返す（LIMIT 1 相当）

#### テスト: 異常系

- 存在しない `id` では `null` を返す（例外にしない）
- テーブル名が文字列でないとき拒否する
- 存在しないテーブル参照は SQLite 例外になる

---

### update

- 条件に合う行を更新し、更新後の対象行を返す
- 対象0件のときは `null`

#### テスト：正常系

- 存在する行を更新すると、更新後の値が返る
- 更新後に `read` しても同じ値が得られる
- 一部カラムのみ更新でき、未指定カラムは維持される

#### テスト: 異常系

- 対象0件のとき `null` を返す（例外にしない）
- テーブル名が文字列でないとき拒否する
- 制約違反の更新は SQLite 例外になる
- 存在しないテーブル参照は SQLite 例外になる

---

### delete

- 条件に合う行を削除し、影響件数を返す

#### テスト：正常系

- 1件削除で戻り値が `1` になり、以降 `read` は `null`
- 複数件削除できる場合、戻り値が削除件数と一致する
- 対象0件のとき戻り値は `0`（例外にしない）

#### テスト: 異常系

- テーブル名が文字列でないとき拒否する
- 存在しないテーブル参照は SQLite 例外になる
- 条件指定が仕様上必須なのに欠落している場合は拒否する（必須なら）

---

## 検索

### search

- 正式な一覧／検索 API
- 条件ビルダー（内部は and/or 木）と `limit`、cursor（`id` 昇順）を受け付ける
- 戻り値は `{ items, nextCursor, hasMore }`
- `nextCursor` は生の `id`（次ページがなければ `null`）

#### テスト：正常系

- 条件なし（または全件相当）で `items` が `id` 昇順になる
- `limit` 未満の件数では `hasMore=false`、`nextCursor=null`
- `limit` ちょうど／超過で次ページがあるとき `hasMore=true`、`nextCursor` が最後の item の `id` になる
- `nextCursor`（生 `id`）を次の呼び出しに渡すと、続きのページが重複なく得られる

#### テスト: 異常系

- テーブル名が文字列でないとき拒否する
- `limit` が 0 以下や非数のとき拒否する（または仕様で定めた扱い）
- 存在しないテーブル参照は SQLite 例外になる
- 不正な cursor（存在しない型など）は拒否または空ページ（一方に固定して実装）

---

### list

- `search` の別名である
- 引数・戻り値・副作用は `search` と同一

#### テスト：正常系

- 同じ引数で `list` と `search` の結果が一致する
- `list` も `{ items, nextCursor, hasMore }` を返す
- cursor ページングが `search` と同様に進む

#### テスト: 異常系

- `search` と同じ入力で同じ拒否／例外になる
- テーブル名が文字列でないとき拒否する
- 存在しないテーブル参照は SQLite 例外になる

---

## 条件ビルダー

ビルダーは公開 API。and/or の木構造は内部表現とする。  
演算子: `eq` / `ne` / `lt` / `gt` / `lte` / `gte` / `in` / `like` / `isNull` / `isNotNull`

### whereBuilder（search から利用）

- カラム条件を積み上げ、ネストした and/or を表現できる
- `search` の結果集合を絞り込む

#### テスト：正常系

- `eq` で一致行だけが返る
- `and` で複数条件の積集合になる
- `or` で和集合になり、ネスト（例: `and` の中の `or`）が意図どおり解釈される
- `in` / `like` / `isNull` / `isNotNull` がそれぞれ期待どおり絞り込む
- 比較演算子（`lt` / `gt` / `lte` / `gte` / `ne`）が数値または順序付け可能な値で正しく動く

#### テスト: 異常系

- カラム名が文字列でないとき拒否する
- `in` に空配列を渡したときの扱いが仕様どおり（拒否または0件）で安定している
- 存在しないカラム参照は SQLite 例外になる
- ビルダー未完成（条件なしで必須なのに壊れている等）な入力は拒否する

## 梱包（モジュール境界）

コードテストというよりランタイム境界の確認。v0.1.0 の受け入れに含める。

### bunSqliteExportGuard

- Bun 上では `@b4moss/crudian/bun-sqlite` を import できる
- Node 上では読み込み時に誤 import を示す明示エラーになる

#### テスト：正常系

- Bun で `createCrud` を import できる
- 共有契約 `@b4moss/crudian` は Bun / Node 双方から import できる（契約のみ）

#### テスト: 異常系

- Node で `@b4moss/crudian/bun-sqlite` を import すると、誤 import を示すメッセージで失敗する
- エラーメッセージに「誤って import」に相当する案内が含まれる
- Bun 以外の実行で `bun:sqlite` 生エラーだけにならず、ガードが先に働く（Node 経路）
