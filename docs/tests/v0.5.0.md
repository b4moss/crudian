## #47 — count / total

### bun-sqlite（参照実装）

パッケージ: `@b4moss/crudian/bun-sqlite`  
ランタイム / テスト: Bun + `bun:test`  
DB: 呼び出し側注入の `bun:sqlite` `Database`（テストでは `:memory:`）

### bun.count

- 条件に合う行の件数を数値だけで返す
- SQL イメージ: `SELECT COUNT(*) FROM table [WHERE ...]`
- `where` なしはテーブル全件数
- `where` ありは `search` と同じ条件集合の件数

#### テスト：正常系

- 空表で `count(table)` が `0` を返す
- 複数行を挿入したあと `count(table)` が行数と一致する
- `where` ありで一致件数だけを返す（例: 名前一致が2件なら `2`）
- 条件に0件のとき `0` を返す（throw しない）
- `eq` / `and` / `or` / 比較 / `in` / `like` / `isNull` / `isNotNull` で絞った件数が、同じ where の `search(...).items` を全件取得した長さと一致する（limit を十分大きくした場合）
- Facade に `count` が関数として存在する

#### テスト: 異常系

- テーブル名が文字列でないとき拒否する
- 存在しないテーブル参照は SQLite 例外になる
- `in` に空配列を渡したときの扱いが `search` と同じ（拒否または0件。一方に固定）
- カラム名が文字列でないとき（where 経由）は `search` と同じ拒否になる

### bun.searchTotal

- `search` の戻りに `total` を常時含める（offset / cursor いずれでも）
- `total` は `count(table, { where: query.where })` と同値
- cursor 経路の検証は `paging: "cursor"` を明示する（#51 以降）

#### テスト：正常系

- 条件なしで全件 N 件のとき、任意の `limit` でも `total === N`
- ページ途中（例: N=5, `limit=2`）で `items.length === 2` かつ `total === 5`
- cursor を進めた2ページ目以降でも `total` は同じ N のまま（`paging: "cursor"`）
- `where` ありで一致 M 件のとき、ページングしても `total === M`
- `hasMore=false` の最終ページでも `total` は全一致件数のまま
- 0件のとき `items` は空、`hasMore=false`、`total === 0`（cursor 時は加えて `nextCursor=null`）

#### テスト: 異常系

- `limit` 不正など既存の `search` 拒否はそのまま（`total` 追加で緩和しない）
- 存在しないテーブル参照は SQLite 例外になる

## #51 — offset / cursor ページング

### bun.searchPaging

- `SearchQuery.paging` で `"offset"` / `"cursor"` を切り替える
- 未指定は `"offset"`（`offset` 未指定なら `0`）
- offset 戻り: `{ items, total, offset, limit, hasMore }`
- cursor 戻り: `{ items, nextCursor, hasMore, total }`
- `ORDER BY id ASC` は両モード共通

#### テスト：正常系

- 引数なし（または `paging` 未指定）の `search` が offset 形を返す（キーに `offset` / `limit` / `total` / `hasMore` / `items`。`nextCursor` なし）
- `paging: "offset"` 明示でも同様。`offset=0`・既定 `limit` で先頭ページが取れる
- N=5, `limit=2` で `offset=0` → 2件・`hasMore=true`・`total=5`・返却 `offset`/`limit` が入力どおり
- 続けて `offset=2` → 次の2件・`hasMore=true`・`total=5`
- `offset=4` → 1件・`hasMore=false`・`total=5`
- `where` ありでも `total` は一致全件数、`offset` でページが進む
- `paging: "cursor"` で既存どおり `nextCursor` / `hasMore` が進み、戻りに `offset`/`limit` フィールドが無い
- 同じ引数で `list` と `search` が deep equal

#### テスト: 異常系

- `paging: "offset"` かつ `cursor` が `null` 以外 → 拒否
- `paging: "cursor"` かつ `offset` が渡されている → 拒否
- `offset` が負数・非数 → 拒否
- `limit` が 0 以下や非数 → 拒否（既存どおり）
- 不正な `paging` 値（例: `"foo"`）→ 拒否

---

### drizzle.searchPaging

#### テスト：正常系

- デフォルトが offset 形
- `offset` 進行と `total` / `hasMore` が bun-sqlite と同趣旨
- `paging: "cursor"` で cursor 形が維持される
- `list` === `search`

#### テスト: 異常系

- 相反入力（offset↔cursor）の拒否
- 不正 `offset` / `limit` の拒否

---

### prisma.searchPaging

#### テスト：正常系

- `await search` のデフォルトが offset 形
- offset 進行と cursor 明示が契約どおり
- `await list` === `await search`

#### テスト: 異常系

- 相反入力・不正 `offset` / `limit` の拒否

## 回帰（スモーク）

### regressionAfterTotal

- v0.1〜v0.3 の振る舞いを壊さない（`total` 追加とデフォルト paging 変更以外）
- cursor 検証は `paging: "cursor"` を付ける
- 条件ビルダー / upsert / bulk* / transaction が引き続き動く

#### テスト：正常系

- `create` → `read` が行を返す
- `paging: "cursor"` の `search` で `items` / `hasMore` / `nextCursor` が従来どおり進み、`total` がある
- デフォルト `search` が offset 形でページできる
- `list` と `search` が同結果
- `upsert` / `bulkCreate` など既存 extended のスモークが通る（触る範囲でよい）

#### テスト: 異常系

- `read` 未ヒットは引き続き `null`
- `update` 0件は引き続き `null`
- 不正 `limit` は引き続き拒否
